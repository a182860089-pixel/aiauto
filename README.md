# 病例自动传 MVP

项目已拆分为两个独立项目：

- `exe/`：Electron 桌面版，可打包 Windows 安装程序
- `web/`：网页端图片识别与 Excel 导出

分别进入对应目录执行各自 README 中的命令即可。

这是一个可直接运行的最小原型，用来验证以下链路：

- 上传病例图片
- 选择病种模板
- 勾选需要抽取的字段
- 查看预填 JSON 结果
- 模拟提交流程

## 运行

```bash
npm install
npm run dev
```

## OCR 导出 Excel

首次运行可以在桌面应用中填写一个或多个硅基流动 Key（换行或 `|` 分隔），点击“安全保存 OCR 设置”。Key 使用 Windows 本机加密存储，保存位置不在项目目录，也不会进入 Git；程序会在前一个 Key 失败时自动尝试下一个 Key。

当前默认视觉模型为 `Qwen/Qwen3-VL-8B-Instruct`。从图片生成 Excel 也可以直接执行：

```powershell
npm run ocr:excel -- "D:\path\to\病例截图.png" "D:\path\to\病例结果.xlsx"
```

未指定输出路径时，文件会保存到 `ocr-output/`。程序会保留识别到的表头和逐行单元格，并生成可筛选、冻结首行的 `.xlsx` 文件。


先设置硅基流动密钥（也可以直接在页面输入框临时填写）：

```powershell
$env:SILICONFLOW_API_KEY = "你的密钥"
npm run dist:win
```

安装包会输出到 `release/`。在桌面应用中填写规培平台账号和密码后，点击“登录平台并自动填入”，程序会打开登录页、自动登录、进入“住院病种记录”、打开新增窗口并填入已勾选字段。程序只会填入字段，不会自动点击最终“确定”。账号密码仅通过本次运行内存传递，不写入源码。

浏览器动态识别使用兼容 OpenAI Responses API 的函数调用。页面中需要分别配置浏览器智能体 API Key、接口地址和模型；默认接口为 `https://api.aigo0.com`，默认模型为 `gpt-5.5`。该代理目前不支持图片输入，因此浏览器智能体通过页面文字、控件属性和同源 iframe 摘要进行动态判断。

首次成功完成填入后，程序会把点击顺序和字段映射保存到 Electron 用户数据目录的 `browser-workflow-template.json`。后续运行优先回放本地模板，动态字段仍使用当次 OCR 结果，不再调用浏览器智能体 API。模板因网页改版失效时，程序会自动回退到 API 模式重新学习并覆盖模板；也可以在自动化日志区域点击“清除模板”手动重置。

## 说明

当前版本是演示型 MVP：

- OCR 已接入硅基流动 OpenAI 兼容视觉接口，模型可在页面中修改
- 字段勾选、模板切换、预览输出和独立浏览器填入已打通
- 选择已有 `.xlsx` 模板后，程序保留模板第一行表头、原有数据行和格式，只将图片中能明确对应的非空字段追加到模板末尾；图片中的额外列不会新增，无法对应的模板列保持空白。未选择模板时生成通用 `OCR识别结果` 工作表
- OCR 页面会展示全部识别行和完整原文，便于在导出前核对；对于分辨率较低、倾斜或被遮挡的图片，仍建议人工复核
